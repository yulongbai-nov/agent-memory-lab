# Public synthetic Luna writer comparison — preregistration

This is a seen-regression comparison, not a blind holdout or production deployment. The four public synthetic DSH fixture bytes are fixed against the earlier R2 digests. Normal native ingest and the production selector construct each exact R2 prompt; all four R2 prompt hashes are asserted. The existing oracle is not an input to selection, request construction, or inference. Semantic evaluation is performed separately against the previously frozen case requirements, with manual review of every claim and every supporting quote; structural acceptance or an empty list does not by itself count as a semantic pass. Preserve raw public synthetic visible outputs and exact references for reassessment.

The predeclared cap is four independent Responses requests, one per case, model `gpt-6-luna`, reasoning `low`, `store:false`, no tools or previous response, nonstreaming, output limit 384 tokens, six minutes total and at most 75 seconds per request. The API output budget includes reasoning tokens and is not comparable to the local model's generation count. No retry or selective case rerun. A dedicated proxy instance must report 4-request and 384-token limits and an empty request ledger before execution. A mismatch or missing actual outgoing hash stops subsequent requests. API/model availability and acceptance of this schema are not established by offline preflight.

The response wire uses strict Structured Outputs. The canonical candidate-v2 schema uses `oneOf` for mutually exclusive `decision` versus `change`/`correction`/`todo` branches and `const` for singleton values; the wire translates these to `anyOf` and singleton `enum`. Since the branch kind values are disjoint and the remaining constraints are unchanged, exactly one branch can match and the two schema acceptance sets agree. The true candidate-v2 validator subsequently validates each returned value and exact alias, then validates the mapped canonical references and computes original UTF-8/UTF-16 spans. The wire schema is not byte-identical to the local schema. OpenAI documents [supported Structured Outputs and nested anyOf](https://developers.openai.com/api/docs/guides/structured-outputs) and [Responses format](https://developers.openai.com/api/reference/resources/responses/methods/create); offline preflight does not establish provider acceptance. The completed trial and its limits are recorded in the [public synthetic result](results-20261112.md).

The compared provider, model, tokenizer, runtime, API reasoning budget, and provider schema injection differ from local R2; observed differences cannot be attributed to a single variable. Calls send only the four checked-in public synthetic prompt bodies. They are never connected to private archives, memory relay, or the default writer. Results are explicitly opt-in, local, and contain no key, authorization header, or opaque reasoning; provider statuses, requested/reported model and effort, bounded assistant output text/refusal, and reported usage are kept even when the output is invalid or incomplete. Explicit model or effort mismatch cannot validate. Per-request usage can remain unknown when the client loses a body; independently recorded proxy cumulative usage and terminal counters are preserved, including on result-write failure when possible. If even the fallback file cannot be written, only the allowlisted aggregate is emitted to stderr and the original failure remains primary. Missing status/usage remains unknown. `validated-needs-semantic-review` is not approval.

After `npm run build`, `node benchmark/writer-luna/run.cjs --preflight` is the default zero-model verification. The separately reviewed launch must start an otherwise unused restricted proxy with `requestLimit:4, outputTokens:384`, provide only its gate token to the runner, create a fresh owner-only system-temp directory named `synthetic-luna-writer-results-*`, and explicitly invoke `--run DIRECTORY`. The runner records a single-use lock named `synthetic-luna-writer-<SHA256 of frozen manifest>.once` directly in the active system temporary directory before sending and writes a separate result file. This lock protects runs sharing that temporary directory; removing it or changing temporary directories defeats the guard, so the launch operator must preserve it and the run receipt. A failed or uncertain attempt is not retried. Do not change the recorded R1/R2 outputs or once-locks.
