# ADR · 本机 SQLite 索引与迁移

## 决定

CouchDB 继续作为跨端同步 hub。本机使用 Node 24 内置 SQLite 按条目、批注、批次和 checkpoint 增量提交。接入、精确证据、查询、批注与同步接口沿用原定义。带范围和筛选条件的查询先在 SQL 过滤，精确证据按范围、条目和版本定位。无筛选的整项目视图及派生整理仍可能扫描该项目。SQLite 使用 DELETE journal，受限 MCP 以只读模式打开。

选型依据是实际首次回填。在 JSON 索引约 108 MiB 时，11 次续读花费约 25 秒，峰值内存约 1.55 GiB。每次写入解析和重写整个索引。改为 SQLite 复用成熟事务、行级查询与操作系统锁，同时保留原有 CouchDB 同步协议和私有原件库。

## 保留与恢复

私有原件库保存已捕获的源字节。SQLite 中的来源及版本映射、导入断点、幂等批次，以及用户批注、确认、变更和纠正账本需要保留。来源已变化或缺失时，旧的证据映射也需要保留。可重建的部分包括搜索字段、SQL 索引、候选目录与 Wiki 派生快照。用户账本和旧版本映射不应按缓存清理。

新目录沿用 JSON，显式运行 `node bin/memory.cjs migrate-index --dir <private-dir> --project <project>` 才迁移。迁移涉及该目录内所有范围。先停止使用该目录的旧版本写入进程和后台采集，再在同一私有目录创建并核验 SQLite 后原子启用。保留原始 `archive.json` 和独立原件。原 JSON 只代表切换前的状态。切换之后如需回退，先停写，再执行 `export-index` 输出含最新内容的私有 `archive-export.json`。核验导出和原件引用后，才可在维护期间恢复旧格式。导出拒绝覆盖已有文件。
