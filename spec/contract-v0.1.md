# 记忆数据契约 v0.1（提案）

## 目标和范围

优先找回过去决定并接续未完成任务。本文定义 v0.1 的事件与来源引用。当前代码提供本机归档、查询、复核、CLI、MCP 和网页。知识图谱、跨 Agent 主动协作与训练仍属规划。[可运行行为与验证矩阵](engineering-quality.md)

当前查询按时间和关键词返回有上限的话题候选。选中话题后可查看时间线、复核过的决定和待办，并按归档版本回读证据。排序使用确定性规则，语义召回质量和复杂分支冲突仍需单独验收。

关键词可匹配源记录，也可匹配已复核的话题与正文。复核项命中时仍须在同一项目取得它引用的准确源版本。时间窗口沿用源时间边界。MCP 的时间线在筛选后的行上返回总数、偏移量和是否还有后续页。

Tier0 保存可获得的原始会话、工具轨迹、附件引用及用户确认的纠正，常规写入追加；Wiki、图谱、索引、结构化记忆与当前上下文是可修订、可重建的派生物。其他层级编号待定。Git 保存设计与代码演进，真实数据使用专门存储，不自动进入公共 Git。十一月 butler 的 Markdown/journal/ledger/grep 设计仅作 benchmark 基线，不是最终架构。

## 事件与来源

事件不可变、稳定 `event_id`，`idempotency_key` 在导入域唯一；相同标识和完全相同内容可重放，不同内容碰撞必须拒绝或交由明确处置，不能覆盖。不同设备和 Agent 应独立生成唯一标识；ID 的生产生成算法待定。`memory_id` 绑定记忆对象，`scope` 区分用户和项目。`valid_time` 描述事件实际适用时间，`observed_time` 是系统获知时间，不能用导入时间或设备时钟直接决定胜负。

`source_refs` 可有多个，包含 harness、session、源版本、稳定消息 ID、展示用轮次范围、采集时间和定位方式。消息 ID 与源版本是依据，轮次只作展示，引用消息须在范围内。原生链接或归档原文应可核查；不可获得时标记 `unavailable` 且值为空，不造链接。示例中 `synthetic://` 对应同一示例文件内的合成归档，不代表真实链接。Schema 校验单条事件；本仓库验证器额外检查示例归档中的消息、引用、幂等和关系，不验证真实链接可达性或来源真实性。

`interpretation` 可记录系统误解；`correction` 指向被纠正的解释，表达用户指出系统误记；`change` 指向旧决定，表达用户真实改变想法。它们追加而非抹去历史。 本机批注的 `target` 与 `revises` 定位被修订的审核及旧证据；纠正可另带 `evidence` 指向同范围内后来的独立消息版本。查询的 `citation` 仍是旧证据，`effectiveCitation` 在有新证据时指向支持纠正的新来源。只提供人工纠正文字时，不把旧证据冒称为新依据。读取证据时如提供 `source`，其 Harness、实例和会话必须全部匹配；旧调用可省略它。同步包含 `evidence` 的纠正前应先升级各端，旧端的字段白名单会拒绝这些记录。批注/审核应关联记忆 ID 与被修订事件 ID（v0.1 的记忆版本标识），明确纠正应及时反映在当前视图；文件变动、自动推断或含糊改动可以成为待核实候选，不自动成为用户决定。通知人工改文件后应读取新版本并关联受影响记忆；多个来源可以共同支撑同一记忆。本文只验证引用结构，不实现文件监控。

合成示例先记录“作为起点”，系统误读为建设基础，用户纠正为 benchmark 基线，并形成已确定决定；后续另有一条真正改变决定的事件。示例按事件子集可观察纠正后的基线与之后改变，时间线仍保留全部内容。

## 五种界面状态与投影

v0.1 将 `basis` 与 `lifecycle` 分开，映射优先级：`cancelled` → 已取消；否则 `superseded` → 已替代；否则 `confirmed` → 已确定，`proposed` → 待决定，`uncertain` → 待核实。测试覆盖五种标签。较新、明确且适用同一范围的决定优先；晚导入或讨论本身不自动推翻旧决定，歧义、并发矛盾保持事件并呈待核实，明确解决事件指向相关事件。这里是投影要求，当前验证器不声称实现完整时序投影或冲突解决算法。

独立归档的合成离线编辑已通过临时 CouchDB 汇合，采集、读取与批注角色分别校验。浏览器可离线打开主动保存的已审核摘要和草稿。原文与候选接口保持联网查询。Mac 私网入口可按指定身份提供 HTTPS，真实手机断网重开与跨主机部署仍需分别验收。[手机接入](mobile-access.md)

## 验收和限制

`npm test` 校验 schema、源引用存在与范围、事件 ID/幂等键、修订目标及同记忆同范围、五种映射、纠正与改变的区别，并执行正反例。相同事件重放按规范化 JSON 视为一次；相同去重键的不同事件拒绝。实验使用合成数据。来源附件内容、跨源消息顺序、循环引用、完整可达性、故障恢复、权限与并发投影未作全面验证。

每日回顾计划检查新增与受影响历史、合并重复摘要、检查分歧、更新 Wiki/索引和候选 Skills，保持证据追溯；具体运行时间、自动发布权限和保留/删除策略待定。训练数据将是可追溯、版本化派生产物，目前不训练。
