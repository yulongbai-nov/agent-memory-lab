# 设计决定与开放问题

- 已选 CouchDB 作为同步主选型；Node PouchDB 是已试验客户端，单节点实验不是生产、移动或安全验收。
- Tier0 常规追加；衍生视图可重建。纠正误记与实际改变决定是不同事件，显式解决并发歧义。
- 范围优先用户与项目；未来团队、授权边界和隔离策略待设计。
- 采用可验收场景与 proposal/spec/design/tasks 风格可以兼容 OpenSpec 工作方式；没有安装或运行 OpenSpec，亦未决定 Skill、CLI、MCP、Hooks 与 UI 的最终组合。
- 待决定：每日执行时刻、自动改进发布权限、原始材料保留/删除政策、其他层编号、手机缓存策略、附件归档、来源 URL 验证、产品入口与训练数据治理。
- ID 生成、去重域与跨设备冲突治理、修订图无环、信任级别与隐私控制需在实现前进一步设计。当前 Schema 和验证器是具体提案，不是最终实现。
