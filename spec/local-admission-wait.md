# Local admission wait: proposed contract

- The complete model SHA-256 and existing sandbox canary remain mandatory. Model preparation precedes the runner. The runner has a 60-second monotonic budget covering sandbox verification, admission waiting, identity/config recheck and inference; the admission phase has at most 15 seconds within that budget. A low sample waits at most 1 second before resampling. Exactly 45% is sufficient. Time consumed by each sample counts. No operating-system cache eviction, unrelated process termination or threshold reduction is performed.
- Successful admission is necessary but not sufficient: immediately before spawning, recheck the previously hashed model's regular-file identity and the resolved identities of the inference and sandbox executables, and verify the private prompt/schema bytes and immutable invocation configuration. Changes fail closed; stat is a change detector after the complete SHA, never a replacement for it. No rehash or silent acceptance follows a change.
- The helper accepts a monotonic clock, sample, cancellable sleep, an absolute deadline and an optional AbortSignal so all behavior is testable without a real model. Exhausting only the admission window returns MEMORY_ADMISSION; invalid/unavailable samples return MEMORY_UNAVAILABLE; deadline exhaustion returns TIME_LIMIT; cancellation returns CANCELLED. No inference starts for these results. Cancellation also stops a child already started by this runner, never other processes.
- Report only safe wait duration, sample count and final percentage plus an explicit internal inference-started flag. Keep the latter distinct from a model call count: admission failure remains zero inference even when metrics exist. No prompt, model path, process command, weights or private contents enter the report. Existing 25% running pressure, RSS and output protections remain unchanged.

Synthetic acceptance covers persistent low pressure, recovery, exact threshold, invalid/failed samples, cancellation before and during wait, exhausted overall deadline, model/executable/config changes, and no spawn when checks fail. Tests use injected stubs and fixture files only, not the production model or private data.
