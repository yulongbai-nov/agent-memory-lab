# 本机待审草稿读取契约

决定回溯和未完任务接续仍以原件、版本和用户复核账本为准。这里提供人工打开本地 Writer 候选的只读入口，「待核实」描述草稿生成时的候选性质，读取器不查询后续是否有独立批注或相同决定。当前正式决定和历史分别通过 `current` 与 `timeline` 查询。新增复核仍由用户经既有 `annotate` 流程选择并提交证据。

## 命令和读取范围

- `memory draft-list --dir PRIVATE_DIR --owner OWNER --project PROJECT` 列出该范围当前最新批次。只返回快照标识、生成时间和最多四项的 `id`、类型、状态、引用数。候选正文和引用只在明确选择详情时返回。`no-draft` 表示尚无草稿，`empty` 表示最近一批通过校验但产出零候选。历史候选和待办另有记录。
- `memory draft-show --dir PRIVATE_DIR --owner OWNER --project PROJECT --id ID` 只打开一项。三个范围参数均须显式给出，不使用默认档案，不接受通配、任意路径、跨项目查询或批量详情。两条命令只输出 JSON，使用同一私有目录校验，以只读方式打开归档。
- 候选 ID 由完整 `latest` 文件字节的 SHA-256 和一基序号构成。范围键包含在文件中，绑定本次列表所见快照。详情打开文件前，指针已替换或消失时返回 `snapshot-changed`，须重新列表。成功打开并核对 ID 后，详情以该文件描述符所见快照为准；随后发生的替换由下一条命令观察。当前快照内不存在的序号返回 `candidate-not-found`。只有精确同一字节快照复用同一 ID。

## 快照和证据

- 只读取按 `owner/project` 推导的 `latest-*.json`。沿用 Writer 先完成缓存和草稿、最后原子替换 `latest` 的发布顺序。一次命令只读一个已打开的快照，既不拼接新旧批次，也不从缓存、TXT、队列或相邻项目补内容。读时检查私有权限、普通文件、非链接、96 KiB 和完整结构。坏文件返回 `invalid-draft`，不输出文件名、内容或堆栈。输入错误、无效快照和失效 ID 返回简短 JSON 状态及非零退出码。空结果无需读证据；旧档无投影偏移仍可标示其证据限制。
- 每项最多三处证据。详情只查同一 `owner/project/harness/instance/session/item/version` 的原始归档版本，并检查同一完整来源身份的最新已归档版本。当前版本标 `current`，存在较新版本标 `older-version`，旧版本仍是合法证据，逐条使用原引用。精确行缺失、错项目和错来源统一标 `missing`，省去未核实的引用元组及候选正文。即使别处有同名条目，也不借用。
- 原件状态单独显示 `verified`、`source-only`、`missing-locally`、`integrity-failed`、`too-large` 或 `unknown`。精确引用的字段和 UTF-8/UTF-16 半开区间校验最多装入 1 MiB 原件。较大的原件按块校验哈希。只有引文同时匹配同一精确版本的合格脱敏输入投影、归档预览和原件跨度，才标 `verified-original` 并返回定位。无偏移的旧档、原件缺失或原件超过模型投影的 1 MiB 上限时，精确匹配归档预览的引文标 `archived-preview-only`。不匹配或完整性失败时标 `unverified` 并省去引文。任一引文未能核实时省去候选正文。输出不含原件正文、文件路径、原始模型结果或输入提示。

## 合成验收

使用真实命令和已安装发行包验证已核实引用、候选空列表、旧源版本、旧档无偏移、缺失／破损原件、坏文件、跨项目与来源碰撞、指针替换和无写入。用严格 TypeScript 校验磁盘数据及输出。新增入口只在本机 CLI 注册，网页、默认 MCP、同步和既有审批账本保持独立。验收不调用模型，也不打开私有运行档案。
