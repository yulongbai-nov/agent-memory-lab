# Local draft recovery: proposed contract

This is a rebuildable, scoped draft queue. It does not alter the source archive, ingest checkpoints, review annotations, or approval state. A processed draft is not an approved decision.

- Discover in bounded pages by monotonic archive insertion sequence, not event time. A turn's latest insertion sequence is its discovery key; a later terminal, message, revision or correction must rediscover the turn even when its original timestamp is old. Inspect completed and failed/interrupted turn markers over the same full scope, not just a recent window. Paginate large turns as well as the catalog; don't treat a temporary budget boundary as an exclusion.
- Queue identity binds owner/project, full source, exact item version, and selector/prompt version. Durable private state stores only bounded exact references and the selection needed to reproduce a pending batch. Ineligible items receive explicit reason codes; missing originals, unclosed turns and other recoverable conditions must be reconsidered after a relevant later source revision or trigger. Selection, per-turn continuation and discovery cursor commit atomically so interruption cannot lose input.
- Before inference, save pending references and selection under the per-scope writer lock. On admission, model, validation, or write failure, retain that same pending work and do not commit it as complete. Retry must re-resolve exact scoped versions, verify originals, and enforce all existing selection and byte bounds. If an exact input becomes unavailable, report a retryable reason rather than silently substituting another record.
- Write the validated output under its deterministic input/version/model key, then atomically record completion and advance queue state. A crash may require re-running inference if it occurs before durable cache creation, but replay must not accept duplicate outputs or create duplicate reviews. An already durable validated cache is usable for recovery. Prompt/selector version changes produce a separate rebuildable queue domain.
- Successful empty output consumes its batch. Distinct input versions reenter. Work continues in bounded pages across invocations even when a page contains only excluded candidates; report continuation separately from no work. Persist no unbounded messages or raw original text in queue state. Existing privacy, verified spans, output validation and local draft status semantics remain intact.

## Synthetic acceptance mapping

1. Admission failure then unchanged retry selects the exact same input; after newer excluded turns arrive, it still retries before scanning new work. No actual model needed.
2. At least 20 newer excluded turns and more than 1,500 newer records do not hide old eligible work across bounded resumptions. Excluded work records reasons; processing a completed batch continues rather than selecting cached work forever.
3. A message whose completion arrives later, an earlier-timestamp late insertion, and an exact revision update each enter the correct scope; interrupted turns do not become valid. Large turns and per-run byte/check budgets preserve continuation.
4. Failure or process interruption before pending save, after pending save, after validated output write, and during progress commit never drops a batch or duplicates accepted output. Repeated and concurrent invocations remain scoped, idempotent, and serialize through the existing writer lock.
5. Wrong scope, tampered/missing originals, malformed model output, cache mismatch and selector/prompt version changes fail closed or rebuild explicitly; no review annotations or approved knowledge are generated.

Implementation notes: page archive `versions.seq` under a fixed per-pass fence; each scoped row can trigger a complete same-scope turn lookup, including a terminal in a different page. Durable pending entries bind original references and projection locators/digests, not raw text. A bounded pending queue uses explicit retry eligibility and fair rotation so a poison batch cannot monopolize the worker; a full queue stops cursor advancement. Durable success cache precedes draft publication and queue consumption. The model process runs outside archive/collector/derived locks, while the per-scope local-derive lock serializes selection and consumption.

The worker's per-run scan uses a fixed archive fence, at most 500 pages of 100 metadata rows and a shared five-second scan/selection budget; selection examines at most 5,000 user references and verifies at most 24 originals. `SCAN_CONTINUATION` means more bounded work remains and the next run resumes the same fence. Once the normal candidate high-water is settled, fresh turns enter from that point; an older affected turn can require bounded rescanning of its suffix. `TURN_INVALIDATED` holds an already pending batch whose turn has an interruption or failure; `CONTEXT_BUDGET` holds an individually verified context version that cannot fit alongside its user input. Held references are not marked processed or silently retried as completed. These status reasons do not approve knowledge or advance the ingest checkpoint.
