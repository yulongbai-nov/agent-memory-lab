# Isolated no-cache model hashing

The model preparation path must hash every byte of the configured model on every new preparation. It opens one dedicated read-only, no-follow descriptor; the parent verifies regular-file type, configured size and descriptor/path identity before and after the helper, including device, inode, size, modification/change times and resolved path. The child inherits only that descriptor and uses a fixed system interpreter in isolated mode. Before any read, it verifies the sandbox's private-file and network denials, then requires `F_NOCACHE` on this descriptor. It reads sequentially once and sends each byte both to Python hashlib and the system SHA-256 tool over stdin. Results are accepted only when both digests, full byte count, final offset and identities agree. The helper issues no explicit global-cache or page-eviction command; no alternate ordinary cached read or stat-only digest substitution is permitted.

The helper and its interpreter, system hash tool and sandbox identities must be checked around the operation. Arguments are passed as an array, the environment is constrained, stdout/stderr are bounded and never expose file bytes or private paths, and timeout/cancellation clean up only the process group created by this invocation. A missing or rejected no-cache capability, failed probe, mismatch, change or helper failure is explicit and fail-closed. The existing inference sandbox, full 45% admission threshold, 25% running threshold, RSS cap and pending retry semantics are unchanged. File-descriptor cache policy does not promise zero effects on shared kernel pages or guarantee memory improvement.

Synthetic acceptance covers empty/unaligned files, known vectors, failure and no fallback, short read, concurrent mutation/replacement, symlink rejection, output tampering, timeout, cancellation, package inclusion, and no impact on unrelated processes. Linux tests use controlled stubs/contracts; macOS-specific no-cache and sandbox behavior is separately evidenced on synthetic files. No production model or private archive is needed. Existing new private caches already persist their computed model fingerprint; older entries are not retroactively assigned one.
