合成语义构建使用既有登录的 Codex CLI 和固定公开夹具。提示版本为 `semantic-candidates-v1`，模型请求配置为 `gpt-6-luna` / `low`。成功批次提示为 1,099 字节，输出两个「待核实」候选，四个来源版本及引文全部匹配。该批次计入输入 10,832（缓存输入 0）、输出 202 token。此前四次尝试未通过运行事件校验，未写入成功缓存。四次的 token 用量未知，因此全部尝试总用量和费用均未知。该次验收中，同一输入重跑实际命中缓存，模型调用为 0。后续缓存格式加入了运行来源校验，真实 CLI 与注入测试不能互用缓存；此次修正未再调用模型。

本地构建备选为现有 Qwen3.5 4B。固定公开夹具通过本机断网推理和逐条引用校验，合成复跑命中缓存，模型调用为 0。同一完成轮次的筛选优先选择决定、变更和下一步线索。公开夹具的纯文本草稿通过引用校验，合成回归验证了来源版本变化重算与无变化缓存。一次真实本机每日入口验收通过结构校验，候选为空，因此本次没有私有非空草稿可核验。后续将已知包装和长消息的精确片段投影接入筛选，公开合成夹具验证了原件字段偏移、引文映射和无变化缓存。该修正未再次调用模型，保留之前的私有空结果。试点已显式启用本地草稿，候选仅供本机文件人工审阅，与确认账本及原件库分开。

私有队列与合成构建是分开的入口。一次明确授权的私有脱敏片段已通过宿主机 Codex 的 Luna low 引用验收，详细统计留在本机。此验收没有给模型接入私有 MCP。日常任务的外部语义处理默认仍标为 `requires-user-consent`，03:00 任务先做确定性派生和待处理统计，再按试点配置尝试至多一批本地草稿。合成结果没有写入确定性归档、用户决定或 Wiki。

回答端基准固定为 `gpt-6-luna` 和 `model_reasoning_effort=low`。首轮找到下一步但未调用独立证据工具。复跑改用临时会话、明确要求独立证据工具与结构化结果，沿用同一合成资料和模型配置。完整复跑通过了 find、timeline 和 evidence，使用量为输入 105,035（缓存输入 75,392）、输出 274 token。它包含宿主机上下文和工具调用开销，未核算费用。日常试点的外部模型调用为 0，本地构建用量另行记录。此结果仅覆盖这一 Luna low 合成任务。

Linux 隔离验收另有公开协议回放和受保护模型任务。真实 Codex 与 DSH CLI 分别生成合成原生会话，临时 CouchDB 验证独立归档之间的范围隔离和离线批注汇合。回放使用本地模拟提供方，真实模型任务经有限额的 Responses 代理执行，二者的结果分别核验。[运行方式](../benchmark/harness-e2e/README.md)

文件基线仍用于对照。合成夹具可按关键词直接查到匹配正文；应用将结果组织为最多五个候选，并在时间线携带可点开的归档版本和独立批注。两种方式未做公平的规模、延迟或召回质量评估。

私有适配器是当前版本的本机回退，经过明显凭据和本机路径的规则脱敏。默认可见的是脱敏投影与精确原件引用。独立私有原件库只保存符合条件并捕获成功的原始记录；工具、附件及历史全量覆盖均不能从抽样推定。运行资料留在私有目录，公共仓库与 CI 仅运行合成资料。

本机索引已切换到 SQLite 的事务行写入。迁移保持原件、条目版本、用户账本、批次、checkpoint 和覆盖元数据，旧 JSON 保留。详情见 [本机索引 ADR](adr-local-sqlite-index.md)。真实回填规模和停点仅记录在本机交付目录。
