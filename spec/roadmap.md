# Agent Memory Lab 总体目标与路线图

## 目标与当前范围

建立可追溯、可纠正、可重建的跨 Harness 记忆系统。当前优先本机 Codex 与 DSH 可读取的历史会话及持续增量，以决定回溯、未完成任务接续作为首要验收场景。手机真机验收、ChatGPT 官方导出及远端常在线主机暂缓，保留未来接入路径，不阻塞本机主线。

## 阶段与验收

| 阶段 | 工作 | 验收依据 |
|---|---|---|
| 近期：本机数据 | 盘点已配置来源与可发现的额外配置；按固定完整记录截止点补齐历史，增量接续活跃来源 | 来源身份、范围、截止点、检查点、失败和原件缺口各自可核查；重复导入幂等，失败不错误推进 |
| 近期：日常使用 | 共用 CLI、MCP、Skill，最多五个候选，时间线、当前决定、待办与精确证据 | 在各 Harness 的实际入口验证调用链；范围隔离、引用版本及任务下一步有依据；区分合成验证与私有验收 |
| 近期：持续运行 | 有界采集、自然每日整理、积压与恢复统计 | 可观察自然触发、迟到变更、失败恢复及无变化缓存；退出码不代替覆盖审计 |
| 中期：分层知识 | 工作上下文、主题记忆、事实、决定、任务、Wiki 与经验的可审阅派生层 | 可由来源和版本化规则重建；纠正与真正改变分别建模；缺少证据保留不确定性 |
| 中期：本体与图谱 | 小型版本化类型、关系、决定演进及任务依赖；比较现成组件 | 关系有独立证据，区分生效与获知时间；按同一资料、问题和预算比较收益，不以安装工具数衡量成果 |
| 中期：工程质量 | 逐步严格 TypeScript，统一接口契约、运行时校验和 CI 门禁 | 正常入口回归、生产包实际查询、同一提交的质量和公开合成协议检查 |
| 长期：受控自进化 | 每日反思形成待审知识与候选 Skills | 保留依据、反例、适用范围、版本、独立验证与回退；明确发布权限 |
| 长期：训练资产 | 版本化样本与评测集，小模型后训练 | 来源可追溯，训练与评测隔离，保留纠正、冲突和负例，按独立评测决定采用 |
| 后续扩展 | 代码库协作、团队权限及多端离线使用 | 项目与角色隔离、设备授权撤销、冲突与重连收敛；手机和导出恢复时独立验收 |

## 依赖与复用原则

按 BFS 后 DFS 执行：先覆盖来源和能力清单，再深入验证具体用户场景。原始数据与来源定位支撑检索、纠正及任务接续；其上才构建 Wiki、图谱、技能与训练样本。可以用合成资料提前验证组件，不能因此宣称真实场景通过。

十一月文件、Markdown journal、ledger 和文本检索方案保持为 benchmark baseline。召回读者固定 gpt-6-luna low；整理模型与图谱写入模型分别比较和计量。Graphiti、Hy-Memory SDK、HY 写入模型、OntoSmith 按各自作用和实际缺口评估，不默认全部安装。OWL 语义、类型约束、图数据库和时间查询能力分别验证。

## 数据与验证边界

原始记录和已接受复核事件采用受控追加；普通 Agent 经限定范围只读入口查询。派生索引、Wiki 和图谱可重建。引用绑定项目、Harness、会话、条目和准确版本；只有投影、截断内容或缺失原件时明确标记。

区分系统误解的纠正与用户真正改变决定，沿用已确定、待决定、待核实、已替代、已取消五种状态。较新的抓取时间本身不覆盖已有决定；缺乏历史时间则保留未知。

测试和必要修复后复验按既定授权范围持续推进，逐次保留结果、失败和用量；来源全量导入不构成全量外发许可。公共仓库与 CI 仅使用合成资料。本文件不包含私有覆盖统计、真实试验结果、原话、来源标识、路径或私有报告链接。

## 任务管理

阶段表示依赖顺序，不虚构交付日期。每项工作记录交付物、验收标准、证据范围、未知项和下一步；采用待做、进行中、已验证、暂缓状态。真实运行记录单独保存在私有运行环境，公开文档只记录通用契约与合成验证。后续更新不能覆盖已保留的失败与历史观察。
