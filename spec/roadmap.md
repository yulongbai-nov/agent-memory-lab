# 总体目标与长期路线图

建立由用户掌握、可追溯、可纠正、可重建的跨 Harness 记忆系统。先让本机 Codex、DSH 的可读取会话拥有明确来源和覆盖边界，再用证据回溯决定、接续未完任务。逐步形成可审阅的知识、经验与协作上下文，支撑受控的技能改进和小模型后训练。各项的当前进展见[完成计划](../plan.md)。

## 六项目标与完成条件

| 目标 | 最终产物 | 完成条件 |
| --- | --- | --- |
| 原始数据资产 | 可获得的会话、工具轨迹、附件引用及逐来源覆盖清单 | 来源身份稳定，能够追加和恢复，分别核对已读取记录、已捕获原件和仍缺失的部分。 |
| 分层记忆与知识 | 工作上下文、结构化记忆、Wiki、本体、图谱与可视化 | 项目工作页和知识主题页平级；结论可追到证据和状态，派生层可重建，用户可以审阅和纠正。 |
| 查找与接续 | 时间或话题候选、决定历史、当前状态和未完任务 | 从模糊线索得到约五个候选，选定后回到准确版本并给出有依据的下一步。 |
| 跨 Agent／代码库协作 | 共用 CLI、MCP、Skill 与可控项目上下文 | Codex、DSH 在同一授权范围获取一致结果，项目隔离，跨代码库交接保留来源。 |
| 每日回顾与自进化 | 增量索引、待审知识与经验、候选 Skills | 自然调度可核验，重复运行幂等，自动派生候选保留来源与状态，明确审核层支撑已审知识。受控发布有依据、明确策略、相应复核与回退。 |
| 小模型后训练 | 可追溯、版本化的训练样本及评测集 | 样本能定位来源和授权，保留纠正、时间、冲突与负例，经独立评测决定采用。 |

## 依赖与取舍

按 BFS 后 DFS 推进。先覆盖来源与能力清单，再深入验证过去决定回溯和未完任务接续。来源与版本定位支撑检索及审阅，审阅结果支撑 Wiki、图谱和技能。自动采纳规则仍待设计，独立工程审查服务于质量验收。训练另需数据授权与训练评测隔离。工程质量、运行时校验和跨层兼容贯穿各阶段。

十一月文件、Markdown journal、ledger 和文本检索保留为对照基线。召回读者基准固定 `gpt-6-luna`、`low`，Writer 和图谱写入分别比较与计量。Graphiti 和 Hy-Memory SDK 是候选框架，HY 是候选写入模型，OntoSmith 是候选本体设计工具。按同一资料、问题和预算比较收益，分别验证类型、证据关系和时间查询，再决定是否采用。

原始记录与已接受复核采用受控追加。检索保留精确版本并注明可用性。区分纠正系统误解、实际改变决定与任务执行状态。派生索引、Wiki 和图谱应可重建，历史时点未知时保留未知。

手机真机、ChatGPT 官方导出和远端常在线主机另行验收。团队角色、多设备授权和跨代码库工作流等扩展，以核心本机场景通过后明确的需求为依据。阶段描述依赖顺序，当前状态及负责角色统一记录在[完成计划](../plan.md)。

Graph + Wiki 的查询、来源和时间契约先于组件评估及原型。关系图已使用 Cytoscape.js，时间线已使用 vis-timeline，两个入口均通过公开合成浏览器验收；研究、待决问题和合成案例顺序见[设计与研究](graph-wiki-design.md)。
