# Task state observations

`task-state` annotations append observations about an existing todo review or an exact legacy reviewed-todo source. An annotation root is `{ "kind": "annotation", "id": "..." }`; a legacy root is `{ "kind": "source", "source": { "harness": "...", "instance": "...", "session": "..." }, "id": "...", "revision": "..." }`. `target` must contain the root's exact source, item ID and revision, including when an older review omitted source. Independently reviewed task roots do not merge by title.

`memory annotate --kind task-state` accepts `--task-root JSON`, `--target JSON`, `--parents JSON`, `--state open|paused|completed|cancelled`, `--evidence-kind source|operator` and `--text`. A source observation also requires `--evidence` with an independent exact same-scope message reference; the todo's own reference and turn-end events cannot establish its completion. An operator observation has no evidence field and is labeled as an operator declaration. `--occurred-at` is optional and only records an explicitly known instant; `recordedAt` is assigned on first local append and preserved by replay and synchronization. An occurrence later than its own recorded time is rejected; comparisons use the stored millisecond precision. Neither time chooses which observation wins.

`memory task-list` returns task roots with current heads, status and a `next_step` for open tasks; unmarked tasks retain the old next-step cue while explicitly reporting that their status is unmarked. Paused and conflict tasks remain visible with no immediate next step; completed and cancelled tasks are omitted. `timeline` keeps the original reviewed todo and its current status heads; all historical observations remain available through the annotations ledger. A previously cancelled review is the default state only until a later explicit observation. Historical as-of task status, reminders and execution are outside this contract.

Observations name their causal parents. Concurrent different heads are a conflict and suppress suggestions; a local resolution must cite all currently visible conflict heads. Equal-state heads keep each source or operator assertion. Replication stages the complete immutable batch before checking root, exact references, parents and cycles, so page order does not change validity. Same ID with identical content is idempotent; a differing payload with the same ID is rejected. A local retry of the same input keeps the first system-assigned `recordedAt`.

The archive schema does not need a table migration: JSON and SQLite annotations store the new payload, and the existing immutable sync transports it. Older clients whose annotation validators do not recognize `task-state` reject such a sync batch; update both endpoints before exchanging these records. The original source, ingestion checkpoints and review history are never rewritten. The default MCP surface remains five tools. Its timeline exposes state, label, head count, and up to three whole current head metadata/evidence references per task under a 4 KiB shared budget. Operator evidence is null; observation text is not included. Omitted or oversized heads are flagged with a pointer to local task-list or timeline; full heads remain on the local CLI.
